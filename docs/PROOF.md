# How a PDF claim is proven here

The ADR (`docs/adr/0001-differentiators.md`) says a feature without a fixture and
an oracle is not done. This file defines what that means: which corpora we use
and under which licence, which engines are the oracles, which metrics decide, and
how a tolerance is set without inventing a number. It is the contract; the
corpus itself arrives in Q4 and the first calibration in Q4 too.

## Three tiers of evidence

| Tier | What it is | What it can prove | Where it lives |
| --- | --- | --- | --- |
| **Fixtures with arithmetic** | `tests/fixtures/*.pdf`, generated by `make_fixtures.py`: `calibration.pdf` (11 pages), `book.pdf` (book prose in an embedded serif), `paths.pdf`, `images.pdf` | that a rule is implemented the way the specification says — pixel values are computed, not blessed | committed; documented in `docs/RENDERING.md` |
| **Tier A corpus** | a small, curated set of third-party files covering constructs we do not generate: CJK/Identity-H, Arabic CID, Type 3, CID-CFF, `/ToUnicode`, JPX, CCITT, CMYK JPEG, shading/pattern/transparency | that real files with those constructs open, draw and extract | committed under `corpus/tier-a/` with a manifest and licence texts |
| **Tier B corpus** | whole upstream trees, pinned by commit and fetched in CI, cached | robustness and scale on hundreds of files, run nightly, not per pull request | not committed |

**Decision.** Tier A = our fixtures plus a curated subset of pdf.js files (target
under 1 MB) and, if the Q4 run shows it earns its 1.9 MB, the PDFBox input set.
Tier B = the full pdf.js `test/pdfs` and the veraPDF corpus, pinned by commit and
fetched in CI. Everything committed carries the upstream licence text and the
attribution in `corpus/LICENSES/`; everything fetched is pinned to a commit SHA
and cached by that SHA.

**Packaging consequence.** The corpus is repository evidence, not shipped code:
`corpus/` must be added to `exclude` in the root `Cargo.toml` so the published
`pdf2` crate does not grow by megabytes of third-party PDFs.

## Oracles

| Oracle | How it runs here | Role |
| --- | --- | --- |
| poppler (`pdftoppm`, splash) | native CLI, package `poppler-utils` | in the gate |
| mupdf (`mutool draw`) | native CLI, package `mupdf-tools` | in the gate |
| Ghostscript (`gs`) | native CLI | in the gate when installed |
| pdfium | C library; the comparator runs it as wasm | manual cross-check only — no C dependency in CI |
| pdf.js | Node | manual cross-check only |
| PDFBox | Java | manual cross-check only |

The comparator runs seven engines and six image diffs (pixelmatch, Resemble,
SSIM, butteraugli, DSSIM, FLIP). We borrow its *method* — several independent
oracles plus a ranked diff — not its toolchain: three native CLIs cover the CI
case without Java, wasm or a C library.

## Metrics and how a tolerance is set

Raster comparisons happen at **144 DPI**, one page at a time. Three numbers are
recorded per page:

1. **page geometry** — page count and page size in points after `/Rotate`; must
   match exactly.
2. **text** — extracted text compared page by page (exact for fixtures,
   whitespace-normalised for corpus files).
3. **pixels** — fraction of pixels differing by more than 32/255 in any channel,
   and mean absolute channel error, against each oracle.

Tolerances are **derived from oracle disagreement, not decreed**:

- First measure the spread *between the oracles* on the same page — pdfium,
  poppler, mupdf and Ghostscript do not agree pixel-for-pixel, and
  [JBIG2 decoders disagree visibly](https://nico.github.io/jbig2-bench/).
- Our tolerated distance from a page is the largest distance any two oracles show
  on that page, plus 10%. Where the oracles disagree, a renderer cannot be
  wrong by more than they are.
- **Fallback bound until calibration lands**: 1% of pixels beyond 32/255 at
  144 DPI against the median oracle, and no page may differ in geometry or text
  at all. The Q4 calibration replaces this with measured numbers per construct.

A file outside its tolerance is a **finding**, recorded in `docs/CORPUS.md` with
the three numbers and the oracle spread — never re-blessed silently. A golden
image in `tests/fixtures/golden/` is a regression net, not a correctness proof;
the correctness claim is the arithmetic fixture or the oracle comparison.

## The procedure

```sh
# structure and text, one file at a time (today's CLI: info, pages, text, check)
cargo run -q -p pdf2-cli -- check corpus/tier-a/<file>.pdf
cargo run -q -p pdf2-cli -- text  corpus/tier-a/<file>.pdf

# one page to PNG, today through the renderer's golden binary
cargo run -q -p pdf2-render --bin pdf2-render-golden -- \
    --fixture corpus/tier-a/<file>.pdf --page 1 --scale 2 --bless --out /tmp/ours.png

# the oracles
pdftoppm -r 144 -png -f 1 -l 1 corpus/tier-a/<file>.pdf /tmp/poppler
mutool draw -r 144 -o /tmp/mupdf.png corpus/tier-a/<file>.pdf 1
```

The CLI has no `render` subcommand yet; if the Q4 batch run needs one, it is
added there rather than documented here as if it existed.

## What the oracle also measures: full resolution

The gate compares 4×4 blocks. A dispatch of `.github/workflows/oracle.yml` with
`blocks: 1` measures at every pixel instead, and its result is committed as
`corpus/oracle-summary-1x1.csv` — the baseline anti-aliasing will be judged by
(`docs/RENDERING-QUALITY.md`). Both CSVs carry this renderer's own distance beside
the inter-oracle spread, so "we are within the engines' disagreement" is a
column, not a claim.

## What the oracle also measures: time

The same job that compares pixels times each case's render and checks it against
`corpus/render-budget.tsv` (`docs/PERFORMANCE.md` §Render time). Distance says
the picture is right; time says it is still drawn at the speed the committed
number promises. Both fail the job, and both print the number they failed on.

## Where the oracle cannot judge

- **`/CropBox` and `/UserUnit`.** `cropbox.pdf` is 200×200 pt with `/UserUnit 2`
  inside a 300×200 media box. At 144 dpi this renderer and poppler both produce
  **800×800**; mupdf in its default invocation produces **600×400**, because it
  ignores the crop box and the user unit for the raster size. Two engines that
  disagree about the page's dimensions cannot judge a third, so the page is
  proven by its arithmetic and its golden, and it is kept out of
  `corpus/oracle-cases.txt` with a comment. Re-add it if the mupdf invocation
  gains a crop-box switch.

## What this does not prove

- It does not prove the absence of bugs outside the corpus, and it says nothing
  about pages the corpus does not contain.
- It does not cover print-precision behaviour — CMYK blending, overprint,
  knockout groups — which `hayro` excludes too and Acrobat alone implements.
- Third-party corpus files are artefacts with their own licences: the manifest
  and `corpus/LICENSES/` are the attribution record, and results published from
  the veraPDF corpus must credit it (CC BY 4.0).
- No user files: the proof set is public and redistributable, by construction.

Two numbers worth reading: `calibration#1` (the colour cells) shows the widest
spread, 8.0% of downsampled pixels — poppler, mupdf and Ghostscript disagree on
CMYK conversion, and our naive `k` conversion sits at the same distance from the
median as they sit from each other. `book#1` is 1.3% apart across engines, with
our distance inside it; pages 4, 5 and 9–11 are geometry or embedded fonts and
the oracles agree exactly, so the 1% floor applies.

An oracle that cannot open a file is skipped with a warning rather than failing
the case: Ghostscript on a runner without ICC support prints one, and an engine
that cannot read the page is not a comparison.
